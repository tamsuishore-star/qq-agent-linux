## 4. 18:10 失联事件复盘

### 时间线

| 时间 | 事件 |
|---|---|
| 18:01:13 | 阿里云告警：`112.86.95.115` 登录 ECS（“非常用地登录”） |
| 18:01–18:05 | 我们执行数据权限/视频配置 |
| 18:08:49 | 阿里云“IP 拦截成功” |
| 18:10 | 我们 SSH 22 开始超时 |
| 18:10–18:29 | 22/28817/80/443 全部超时 |
| 18:29 | 你删除两条“拒绝所有流量”规则后恢复 |

### 原因

你按阿里云告警，在安全组里对 `112.86.95.115`、`117.136.19.94` 加了“拒绝所有流量”。  
其中 `117.136.19.94` 正是我们 SSH 的公网出口（`auth.log` 显示 `Accepted publickey for root from 117.136.19.94`，密钥 `dsh-deploy`），所以把我们自己的管理通道切断了。

### 结论

- 不是服务器故障，也不是数据权限变更导致；
- 是**安全组误封自己的出口 IP**；
- 恢复方式是删除那两条 deny 规则。

### 教训

1. 安全组优先用“允许指定来源”，不要用“拒绝所有”处理告警；
2. 管理 IP 会变化，最好用 Workbench 作为应急通道；
3. 高危操作前先确认当前 SSH 出口 IP：`echo $SSH_CLIENT`。
