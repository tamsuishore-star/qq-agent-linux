# 语音回复（tts-say）

你说「发语音 / 念一下 / 用语音说」时，它**用人设把要回答的话念成一条语音发出来**，代替打字。
关键词触发，平时零成本；TTS 走 **Windows 自带中文语音**——离线、免 key、不联网。

## 三步启用

1. 控制台 →「技能」→ `语音回复` → 设置
2. **先保持「演练模式」开启**（默认就是开的）→ 保存
3. 群里说一句 **「发个语音说说你今天干嘛」** → 看会话卡片里有没有 `status: dry-run` 和合成出来的字数/秒数

   - 数字正常 → **关掉演练模式**，正式生效
   - 想换音色 → 见下面「换音色」

## 设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| TTS 引擎 | `sapi` | `sapi` = Windows 自带语音（离线、免 key）；`edge` = 微软神经音色（100+ 个、自然很多，需先装 edge-tts） |
| **音色**（下拉） | `Microsoft Huihui Desktop` | sapi 用第一个；edge 用 `zh-*` 那些（晓晓/晓伊/云希/云扬/方言/粤台…共 15 项） |
| 其它音色（可选） | 空 | 填了就盖过下拉框 —— 选列表里没有的（如 `en-US-JennyNeural` 英语女声）。**只在 edge 引擎下生效**，sapi 会忽略它。一次只填一个真名 |
| 语速 | `0` | -10 ~ 10，越大越快 |
| 音高（Hz） | `0` | -50 ~ 50，**只有 edge 支持**。调高更清脆/少女，调低更沉 |
| 音量 | `100` | 0 ~ 100（edge 下 100 = 正常） |
| 单条字数上限 | `300` | 超了自动截断（优先在标点处断开） |
| 单条时长上限 | `60` 秒 | 按字数 × 语速估算 |
| 冷却 | `60` 秒 | 同一会话两次语音的最小间隔，换个群立刻能发 |
| 投递方式 | `record` | `record` = 语音气泡；`file` = 当普通文件发（气泡不行时的兜底） |
| 触发关键词 | `发语音,说语音,语音回复,用语音,念一下,读出来,…` | 逗号/顿号/空格分隔 |
| **跨会话语音** | **关** | 开启后能把语音发到**别的**群/私聊；需两个开关同时打开（见下） |
| 转达关键词 | `发给,发到,转告,告诉,私聊,…` | **和语音词同时出现**才走跨会话 |
| 单轮跨会话上限 | `2` | 一次会话最多发几条跨会话语音 |
| 跨会话冷却 | `300` 秒 | 同一个目标两次语音的最小间隔 |
| 演练模式 | 开 | 开着只合成不发送 |

改完**保存即生效**（每次执行现读设置），不用重启。

## 换音色：怎么用上 100+ 个神经音色

### 1. 装 edge-tts（一次就够，免费、无需 key）

`<QQ Agent 的 data 目录>` = **QQ Agent 程序所在目录下的 `data` 文件夹**
（安装版一般在 exe 旁边；压缩包版在解压出来的目录里。下面命令里的 `tts-vendor`
是要新建的子目录，直接照抄 `--target` 里的路径、前面换成你自己的 data 目录即可。）

```powershell
python -m pip install -i https://mirrors.aliyun.com/pypi/simple/ `
  --target "<QQ Agent 的 data 目录>\tts-vendor" edge-tts
```

> ⚠️ **必须用阿里云镜像**。清华镜像对 pip 返回 403（WAF 拦 JSON API），
> 官方 pypi.org 在部分网络下连不上。装在 `data\tts-vendor` 而不是 skills/ 里：
> skills/ 被文件监听递归看着，往里写文件会触发热重载。

装错位置也不要紧 —— 技能报「edge 引擎不可用」时，会把**你这台机器上正确的目标路径**
直接打在会话卡片里，照着那条命令重跑一遍就行。

### 2. 设置里切引擎 + 选音色

「TTS 引擎」选 `edge`，「音色」从下拉里挑（默认 `zh-CN-XiaoxiaoNeural` 晓晓）。
然后**先开着演练模式**试一次，会话卡片里会写明用的哪个引擎、几秒。

### 3. 不知道有哪些音色？问它一句

直接说「**你能用什么声音说话**」→ 它会调 `list_voices` 列出真名清单
（默认只给中文 14 个；想要全部 100+ 语种就说「列全部音色」）。
**不要自己编名字** —— 名字不在清单里会被当场拦下并提示正确的那个。

### 兜底行为

edge 装不上 / 网络不通 / 音色名错 → **自动退回 Windows 自带语音**，
并在会话卡片里写明退回原因 + 该执行的安装命令。功能不会哑火。

## 跨会话语音（像 `send_to` 那样把语音发给别人）

**默认关闭。** 要用得**两个开关同时打开**：

1. 控制台 →「技能」→`语音回复`→ 设置 → 打开 **跨会话语音**
2. 控制台 →「设置」→「工具与技能」→ 打开 **允许跨会话发送**（core 的那个总开关）

然后有人说「**用语音转告一下张三**」时，它会：先 `get_chats` 查目标 chatKey → 合成语音 →
发到那个会话。**当前会话里不会因此多一个字**（文字闸门会把 `send_message` / `send_to` 都拦掉）。

### 安全边界（和 core 的 `send_to` 对齐）

| 校验 | 口径 | 拒绝时的提示 |
|---|---|---|
| 技能开关 | `crossEnabled` | 本技能的「跨会话语音」开关没打开 |
| core 开关 | `cfg.tools.crossChatSend === true` | 「允许跨会话发送」未开启 |
| 目标格式 | `^(group\|private):\d+$` | 格式应为 group:群号 或 private:QQ号 |
| 不能是当前会话 | `target !== ctx.chatKey` | 目标就是当前会话，用 `say` 就行 |
| **白名单** | `cfg.allow.groups/private`，空名单需 `allowAllWhenEmpty` | 目标不在白名单内 |
| 单轮配额 | 默认 2 条 | 本次运行已达上限 |
| 目标冷却 | 默认 300 秒 | N 秒内刚给该目标发过 |

> ⚠️ core 的跨会话管控是**硬编码 `send_to` 这个 id** 的（`tool-registry.js:186`），管不到本工具；
> 所以上面这些校验是在本技能里**逐条复刻**的（纵深防御，不是重复劳动）。
> 代价：core 将来改规则时要跟着改。**读不到全局配置时一律拒绝**（fail-closed）——
> 没有白名单校验的跨会话发送是不能接受的。

### 防误发设计

**只有"语音词 + 转达词"同时出现才走跨会话。** 单纯说「发个语音」永远只在当前会话，
绝不会莫名发到别人那里。两个开关任一为关时，它只会告诉用户"功能没开"，**不发送任何内容**。

## 它是怎么做到"只有声音、没有字"的

核心**从不会自动把助手的文字发出去** —— 模型必须调 `send_message` 才说话（`prompt.js:802`，收尾只看 `session.sent`）。所以：

1. 关键词命中 → 钩子往消息末尾追加一条「这一轮改用语音」的指令
2. 模型调 `tts-say__say` 念出内容
3. **模型不调 `send_message` → 群里一个字都没有**

万一模型不听话、直接调了 `send_message`，`before-tool` 闸门会把它拦下来（返回"请改用语音工具"），
所以不会出现"又发字又发音"。

## 返回的五种状态

| status | 含义 | 模型会怎么做 |
|---|---|---|
| `ok` | 语音已发出 | 不再补文字，直接结束 |
| `dry-run` | 演练模式，只合成了没发 | 提示你关掉演练模式 |
| `cooling` | 冷却期内刚念过 | 改用文字回复 |
| `error` | 参数不对 / 拿不到会话 | 改用文字回复 |
| （无 status） | 合成或发送失败（`isError`） | 会话卡片里带原因，模型改用文字 |

**任何一步失败都会明确告诉模型"改用文字"** —— 不会哑火。

## 换音色 / 换引擎

**用 Windows 其它语音**（控制台「音色」下拉第一个，或填全名）：
先跑一句 PowerShell 看本机有哪些：

```powershell
Add-Type -AssemblyName System.Speech
(New-Object System.Speech.Synthesis.SpeechSynthesizer).GetInstalledVoices() | ForEach-Object { $_.VoiceInfo.Name }
```

> 想听更自然的神经音色（晓晓/云希/方言/粤语…）见上面「换音色」章节。

## 把这个技能分享给别人

**只需要打包 `skills/tts-say/` 这 3 个文件**（`skill.json` / `index.js` / `README.md`），
丢进对方的 `resources\app\skills\` 即可，QQ Agent 会自动加载（不用重启，改完文件热重载就生效）。

对方拿到后：

| 要做的事 | 说明 |
|---|---|
| 启用技能 | 控制台 →「技能」→ 语音回复 → 打开 |
| **什么都不用装** | 默认 `sapi` 引擎 = Windows 自带中文女声，**离线、免 key、零依赖**，直接能用 |
| 想换更好听的音色 | 才需要装 edge-tts（一条命令，见「换音色」章节）。**不装完全不影响使用**，只是音质机械一点 |
| 配一次自己的接口/白名单 | 跨会话语音默认**关闭**；要用得自己开「允许跨会话发送」并把目标加进白名单 |

包里的东西**不含任何使用者信息** —— 没有密钥、账号、路径、IP：

- 技能设置存在**使用者自己的** `data\config.json` 里，不在技能目录中
- 音频临时文件、冷却状态也都在 `data\` 下，不在技能目录里
- 提示词里的安装命令用的是 `<QQ Agent 的 data 目录>` 占位符，不是任何人的真实路径
- 运行时若需要给出安装命令，路径由**对方自己的** `DATA_DIR` 运行时拼出来

> ⚠️ 唯一的环境前提：**Windows + PowerShell**（sapi 引擎靠 `System.Speech`）。
> 非 Windows 上技能能加载，但合成会失败并提示"调不起系统语音引擎"。

## 为什么能直接发 wav（不用 silk 编码器）

实测 SnowLuma（OneBot v11）**直接接受 wav 的 `record` 段**，`file://` / 裸路径 / base64 三种写法都成功；
`audio` 段不支持（`retcode 1400 unknown message segment type: audio`），别用。

发送走 `ctx.sender.sendMedia`（`sender.js:348`）而不是直接调 `onebot.sendSegments` ——
前者自带去重、限频、发送前停顿、留档；绕过它会导致"媒体把文字配额吃光后突然发不出话"和重复发。

## 排障

| 现象 | 原因 / 处理 |
|---|---|
| 说了"发语音"没反应 | 关键词没对上 → 改**触发关键词**；或技能被禁用；看会话卡片里有没有工具调用 |
| 还是发了文字 | 闸门只拦 `send_message`；若模型换用别的工具发内容，把**触发关键词**收窄，或把「投递方式」保持 `record` |
| `status: dry-run` | 演练模式还开着 → 关掉 |
| 报"音色不对或系统里没装" | 用上面那条 PowerShell 查真实音色名，填进设置 |
| 一直 `cooling` | 冷却没到点（默认 60 秒）；想立刻再测把**冷却**临时设 0 |
| 语音没出来 / 群里是个文件 | 把**投递方式**改成 `file` 反过来试；或看日志里两种段各自的失败原因 |
| 声音很机械 | sapi 就这样。换 `edge` 引擎（见上「换音色」），或调**音高**（仅 edge） |
| 选了 edge 但声音还是机械的 | 退回 Windows 语音了 —— 会话卡片里写了原因和安装命令，按那条命令装 edge-tts |
| 报"音色 XX 不存在" | 名字拼错了（最常见：把两个名字粘在一起）。说「你能用什么声音说话」拿清单，或直接从下拉选 |
| pip 装 edge-tts 报 403 / 找不到版本 | 镜像被拦。**必须用 `-i https://mirrors.aliyun.com/pypi/simple/`**，清华镜像对 pip 是 403 |
| 合成很慢或超时 | 文本太长 → 调小**单条字数上限**（默认 300 字约 60 秒） |
| 说「转告XX」但没发出去 | 检查**两个开关**都开了吗（技能设置 + 工具与技能）；再确认目标在**白名单**内 |
| 跨会话报"格式应为 group:群号" | 模型自己编了 chatKey → 它应该先用 `get_chats` 查；会话卡片里能看到它调了什么 |
| 跨会话发出去但当前群也冒出一句话 | 闸门只拦 `send_message` / `send_to`；若模型换了别的工具发内容，把**转达关键词**收窄 |

## 文件与落盘

```
skills/tts-say/
  skill.json   清单 + 14 项设置表单（无静态提示词片段）
  index.js     registerTool(say / say_to) + 关键词注入钩子 + 文字闸门 + SAPI 合成
  README.md    本文件
```

- 临时音频：`data\tts-cache\*.wav`，**发完立即删除**（不留垃圾）
- 冷却状态：`data\tts-say-state.json`
- 两者都**不在技能目录里** —— `skills/` 被文件监听递归监听（`plugin-loader.js:565`），
  自己往里写文件会触发热重载 → 内存状态清零，是个自激回路
- 依赖：**无**。不需要联网权限（`skill.json` 里没声明 `permissions`）、不装任何包、不碰 OneBot HTTP
